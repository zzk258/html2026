# 更新日志组件（LogBoard）

定位是**博客式的项目介绍日志**：一个项目写一篇，图文并排，点开是完整正文。
提供新增、编辑、删除、搜索、阅读页、导入导出。纯原生 JS，无第三方依赖，
`file://` 下双击即可用。

## 文件

| 文件 | 作用 |
| --- | --- |
| `log-board.js` | 组件主体，暴露全局 `LogBoard.mount()` |
| `log-board.css` | 组件样式，配色复用 `home.css` 的 `--c-primary` 等变量 |
| `data/net.json` | 网络模块的已发布日志（`id=net`） |
| `data/ops.json` | 运维模块的已发布日志（`id=ops`） |
| `files/<日志ID>/` | 附件实体文件，一篇日志一个子目录 |
| `本地预览.js` | 本地 `localhost` 服务（附件自动写入、读取 data JSON 都需要安全上下文） |
| `清理附件.ps1` | 删日志后清理不再被引用的附件（默认预览，`-Apply` 才删） |

## 在页面里使用

```html
<link rel="stylesheet" href="更新日志/log-board.css">
<script src="更新日志/log-board.js"></script>
<script>
  const board = LogBoard.mount(document.querySelector('#myLogs'), {
    id: 'net',                    // 必填：存储键后缀，不同模块用不同 id 即数据隔离
    title: '网络日志',
    desc: '用一篇文章介绍一个网络项目：背景、做法、结果',
    tags: ['项目介绍', '网络', '交换机', '故障处理']   // 标签输入框的候选词
  });
  board.count();    // 当前篇数
  board.refresh();  // 从存储重新读取并渲染
  board.destroy();  // 卸载（移除 DOM 与弹层）
</script>
```

容器需要有确定高度（例如 `flex:1` 或固定 `height`），列表区才会自己滚动。

## 一篇日志长什么样

列表卡片：封面图（第一张图片）、日期、标签、标题、两行摘要、图片数 / 阅读时长。
点卡片进入**阅读页**：封面大图 + 标题 + 日期/标签/时长 + 正文排版 + 文末图集。
阅读页右上角可以直接「编辑」「删除」。

编辑器字段：日期、标签（逗号或空格分隔，最多 6 个）、标题、摘要（可留空，自动取正文开头）、正文、图片。
图片支持点选 / 拖拽 / `Ctrl+V` 粘贴，自动压缩到最长边 1600px、JPEG 0.8，单篇最多 9 张，**第 1 张自动作封面**。

## 正文语法（轻量 Markdown）

| 写法 | 效果 |
| --- | --- |
| 空行 | 分段 |
| `## 小标题`（也支持 `###` `####`） | 小标题 |
| `- 条目` / `* 条目` | 无序列表 |
| `> 摘要` | 引用块 |
| `**加粗**` | 加粗 |
| `` `代码` `` | 行内代码 |
| `[文字](https://…)` | 链接，新窗口打开 |
| 单独一行写 `[[1]]` | 把第 1 张图片插到这个位置 |

正文里没有用 `[[n]]` 引用的图片（封面除外）会自动收进文末图集，不会丢。

## 数据分两层（这是能和 GitHub Pages 配合的关键）

| 层 | 存在哪 | 作用 |
| --- | --- | --- |
| 已发布 | 仓库文件 `更新日志/data/<id>.json` | 页面启动时 `fetch` 它，作为基线内容 |
| 本地 | 浏览器 `localStorage`：`zzk.log.<id>` | 本机新写 / 改过的条目，只存这些，不复制已发布内容（省配额） |
| 墓碑 | `zzk.log.<id>.del` | 删掉「已发布」里的条目后记一个 id，避免刷新又被 JSON 带回来 |

合并规则：`data/*.json` 的条目 + 本地条目，同 id 取 `updatedAt` 更新的那份；
墓碑里的 id 直接隐藏，并且当 `data/*.json` 里已经没有这个 id 时，墓碑会自动清掉。
所以「本地改了 → 推送新 JSON → 线上刷新」能生效，本地没推的草稿也照样看得见。

`file://` 双击打开时浏览器不允许 `fetch` 本地文件，此时只用 `localStorage`，
推送流程不受影响（本来也是本地写完再推）。

## 导入 / 导出

- 「导出」生成 `<id>.json`（例如 `net.json`），内容 = 当前看到的全部条目（含本地草稿），
  直接覆盖 `更新日志/data/<id>.json` 就是一次发布
- 「导入」读取同格式 JSON（也接受纯数组），按 `id` 合并进本地；换电脑时用它恢复
- 数据里带的是压缩后的图片 dataURL，所以文件会比较大（几篇带图的就能到几 MB），
  提交前留意仓库体积

## 推到 GitHub Pages

1. 本地写日志并点「导出」，把下载到的 `net.json` 覆盖到 `更新日志/data/net.json`
2. 若这篇带了附件，把附件文件一并复制到 `更新日志/files/`
3. 提交并推送：

   ```bash
   git add 更新日志/data/net.json 更新日志/files
   git commit -m "更新网络日志"
   git push
   ```

   或者直接双击项目根目录的 `发布日志.bat`：它会 `git add -A` → 用「更新日志 + 时间」做提交信息 → `git push`，
   没有改动时会提示「没有需要提交的改动」。导出仍然得在浏览器里点，脚本只负责后面三步。

4. 等 Pages 构建完（通常 1 分钟内），刷新线上的网络页即可看到新内容

注意：本地 `file://` 和 `https://<用户名>.github.io` 是两个不同的存储域，
本地写的内容**不会自动上线**，必须走上面「导出 → 覆盖 → 推送」这一步。
换设备打开线上站点，看到的是仓库里已发布的内容；想在另一台电脑继续编辑，
把 `data/*.json` 下载下来用「导入」灌进本地即可。

## 附件与下载

编辑器里可以给日志挂附件（PDF、Word、压缩包、配置文件等），但**只记录文件名、大小、类型**，
文件本体不打包进日志 JSON，而是放在仓库目录。两种放法：

| 模式 | 放哪 | 链接 |
| --- | --- | --- |
| 手动（默认，最简单） | 直接放 `更新日志/files/` | `files/<文件名>` |
| 自动写入 | 组件建 `files/<日志ID>/` | `files/<日志ID>/<文件名>` |

阅读页文末会列出附件，点击即下载（带 `download`）；走相对路径，本地 `file://` 与
GitHub Pages 上都能直接下载，中文文件名会自动做 URL 编码。

手动模式只有一个公共目录，不用记 ID，只要**文件名不重复**即可（重复会指向同一份文件）。

### 自动写入（可选）

浏览器不能凭空写磁盘，但经用户授权一个目录后可以写，组件用 File System Access API 实现：

1. 双击项目根目录的 `启动本地预览.bat`（需要 Node.js），它起本地服务并打开 `http://localhost:8123/home.html`
2. 写日志时点「连接项目目录」，选中 `更新日志/files`
3. 之后**选中附件即自动写入** `files/<日志ID>/`，行尾标「已写入」
4. 删日志时该目录**自动递归删除**，不留残文件
5. 句柄存 IndexedDB，下次打开同一浏览器自动复用

### 删除后清理（手动模式）

浏览器 JS 不能删磁盘文件，手动模式删完日志后跑一次脚本兜底：

```powershell
# 先预览会删什么（不动文件）
powershell -ExecutionPolicy Bypass -File .\更新日志\清理附件.ps1

# 确认后执行删除
powershell -ExecutionPolicy Bypass -File .\更新日志\清理附件.ps1 -Apply
```

脚本读 `data/*.json`，保留仍被任何日志引用的附件，其余文件、以及整篇日志已不存在的目录一并删掉。
注意：只在浏览器里、还没导出推送的日志脚本看不到，先导出再清理。

图片另存：点开大图后底部有「下载原图」，直接把 dataURL 存成 jpg。

## 图片地址安全

只接收组件自己生成的 `data:image/...;base64,` 开头的图片；导入的 JSON 里若混入
`http://`、`javascript:` 等地址会被丢弃，避免把恶意链接当图片渲染。
正文链接只放行 `http(s)://`、`mailto:` 和 `#`。

## 主页里是怎么接的

`home.html` 顶栏三个项目按钮（`data-module="front|net|ops"`），媒体区里
`.lb-slot[data-slot="net"]`、`.lb-slot[data-slot="ops"]` 各是一个日志面板插槽：

1. 点按钮 → `home.js` 的 `setModule()` 给 `body` 加 `module-net` / `module-ops`
2. CSS 按 `body` 类决定显示哪块：前端是侧栏 + iframe，网络/运维是对应插槽
3. 第一次进入某模块才 `LogBoard.mount()` 并缓存实例，来回切换不重渲染、不丢数据
4. 打开主页默认 `module-front`（前端），不记忆上次模块

要再加一个项目（比如「存储」），只需：顶栏加
`<button class="module-btn" data-module="storage">存储</button>`、媒体区加
`<div class="lb-slot" data-slot="storage"></div>`，并在 `home.js` 的 `MODULE_IDS`、
`LOG_MODULES` 和 `home.css` 的可见性规则里各补一条。
